# Sunfire v2.0.0 Release Notes

## Overview
**Sunfire v2.0.0** (`2.0.0+1`) is the v2 feature release. It closes the extension-update loop (updating a scraper no longer leaves a stale duplicate forcing an uninstall), fixes the remaining reader/download/sync edge cases, and ships the two "big" v2 features: **client-side `.tachibk` restore** and **iOS background-download awareness**.

> **Upgrade note**: if you previously had to delete Sunfire before installing an update because of "different keys", that is fixed. Existing installs upgrade in place.

---

## Highlights

### Extension updates no longer require uninstalling
The installed-extension key was derived from *where the install came from* (repo display name, pkg file name, bundled asset name). Updating from a repo could therefore create a **second** install under a different key while the old code lingered — and fuzzy lookups could return the stale version. Now:
- Canonical identity helpers (`extensionIdentityKey`, `extensionVariantIdentityKey`, `sameExtensionIdentity`) key an extension by its **base name**, not where it came from.
- `saveLocalExtension` reconciles away stale variants (memory + disk) so an update *replaces* rather than duplicates — while never deleting the canonical file it just wrote.
- `deleteLocalExtension` and `getInstalledVersion` are variant-aware and return the **highest** installed version, so "update available" never lies.

Corrected the `.js`/`.json` suffix handling (`'mangadex.json'.replaceAll('.js','')` used to produce `'mangadexon'`); stripping is now length-based.

### Client-side `.tachibk` restore (A3)
- **Settings → Backup and Restore → "Restore from .tachibk File (Device)"** lets you pick a Tachiyomi/Suwayomi backup on the device, review every manga it contains, and import the ones you want.
- A self-contained parser reads the `Tachiyomi/backup.json` entry from the archive (sources, categories, manga, favorites).
- Sources are matched to your server by **name + language** (Tachiyomi source ids don't map to Suwayomi ids); unmatched entries are listed as *"Source not installed on server"* and skipped instead of failing the batch.
- Missing categories are created, each resolved manga is added via Suwayomi's url-based `addManga` mutation, and its categories are assigned.
- Per-entry checkboxes; a summary dialog reports imported/failed with per-title messages.

### iOS/macOS background downloads: never silent (B1)
iOS/macOS suspend active transfers when the app backgrounds (no `UIBackgroundModes`). Full native background transfer needs `URLSession` background sessions / `BGTaskScheduler` — a plugin-level spike tracked for v2.1. The realistic v2 behavior is kept (pause on suspend, resume on foreground) and is now **explicit**:
- The queue records whether downloads were mid-flight when the app backgrounded.
- On resume, an "Downloads resumed" notification reports how many transfers were paused and are running again (gated by `downloadNotificationsEnabled`).

## Roadmap items shipped (v2 roadmap Phases 1–3)

### Phase 1 — Close the loops
| Item | What changed |
|---|---|
| **A2** Retry abandoned sync | Abandoned/failed `SyncRecord`s are no longer a dead end. **Settings → Advanced → "Retry Failed Sync"** resets them to `pending` and kicks an immediate flush (`SyncEngine.retryFailedSyncRecords` + `IsarService.getFailedSyncRecords`). |
| **B3** `downloadOnlyWhileCharging` | Wired for real via `battery_plus`: the queue pauses when unplugged and resumes on charger connect (battery + connectivity listeners). The queue screen shows a "waiting for charger" banner. Applies to library auto-updates too. |
| **B6** Paged nav throttle | `_goToNextPage`/`_goToPrevPage` share the same window guard as the webtoon path, so rapid taps can't double-advance. |
| **B7** Single-page progress | A 1-page chapter persists progress/read immediately after load (respecting delete-finished + scrobble rules) instead of waiting for dispose. |
| **B8** Volume promise | `VolumeController.getVolume()` now has a `catchError` fallback like the scrobble calls. |
| **B9** Dead reader branch | Removed the unreachable `index >= _pageUrls.length` branch in `_onPageChanged`. |
| **D1** Third-party install warning | Installing/updating an extension from a non-official repo shows a "third-party — trust at your own risk" confirmation. The Sunfire Official repo is allowlisted. |

### Phase 2 — Polish & trust
| Item | What changed |
|---|---|
| **A1** Auth-error UX | 401/403 responses are classified as auth errors (`GraphQLClientService.authErrorNotifier`); the main shell shows a one-shot **"Server rejected your login — Reconnect"** snackbar that opens Server settings. Cleared automatically on a successful authenticated request or reconnect. |
| **B4** Webtoon memory | Per-page zoom controllers/keys are pruned within a chapter (keep-window ≈ ±40 pages around the current page) instead of accumulating for the whole chapter. |
| **B5** Reader eviction | Byte-eviction no longer evicts currently visible pages (current ±1 are excluded from candidates). |
| **C1** Language badges | `showLanguageBadges` now renders a short language pill on updates cards and library grid/list items; `selectedLanguages` filters the Updates feed (Mihon parity). Default/universal labels (EN/ALL/MULTI/UNIVERSAL) are not badged. |
| **D2** Extension hash verify | `index.json` entries may declare `sha256` (accepts `hash`/`sourceCodeHash` too). Downloaded JS is verified before install; a mismatch refuses the install with a clear error. Absent hashes fall back to the D1 warning (backwards compatible). |
| **C2** Navigation unification | Settings-facing `MaterialPageRoute` pushes converted to go_router routes (`/settings/...`). |

### Phase 3 — Big features
| Item | What changed |
|---|---|
| **A3** `.tachibk` restore | See Highlights. |
| **B1** iOS background | See Highlights + `docs/planning/ios-background-downloads.md`. |

### Accepted / not solvable
- **B2** Android 15 6-hour `dataSync` budget: OS constraint; clean pause + foreground resume already in place.
- **E1** Web platform unsupported (`dart:io`, path_provider, native QuickJS).
- **E2** Extension JS trust floor is inherent to Mangayomi compatibility (mitigated by D1/D2).

`flutter analyze` is clean.

## Known limitations (updated)
- **iOS/macOS**: background transfers still require a native `URLSession` background-session / `BGTaskScheduler` implementation (v2.1 spike). v2 resumes on foreground and now notifies when it does.
- **Android 15**: unchanged 6h `dataSync` budget behavior (clean pause → resume on foreground).
- Extensions still run untrusted JavaScript by design; use **D1/D2** (warnings + optional sha256) to reduce trust.
