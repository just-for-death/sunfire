# Sunfire v3.0.0 Release Notes

## Overview
**Sunfire v3.0.0** (`3.0.0+1`) is the v3 stable release. It promotes the v3.0.0-beta line (tablet/iPadOS navigation overhaul, iOS storage hardening, self-healing image loading) to stable and adds every post-v2.5.0 correctness fix: server-first migration sync, a collision-free synthetic id space, offline-category pull safety, paginated chapter fetching, and an observable QuickJS init status.

> **Upgrade note**: v3.0.0 is a **stable** release (no `-beta` marker). `RepoManager.compareAppVersions` always ranks a stable release above any prerelease, so in-app update checks never mistake this for a downgrade from `v11.0.0-beta` or `v3.0.0-beta`.

## New in v3.0.0 stable (since v2.5.0)

### Universal server-sync for source migration
Every source migration now stays in sync with the Suwayomi server, not just resolvable ones. Modern Suwayomi dropped the `addManga` mutation, so URL resolution falls back to searching the source (title first, then a URL-derived query) and matching the best result by normalized URL/title.

### Collision-free synthetic id space (chapters **and** categories)
Fabricated **positive** synthetic chapter ids shared the unique `serverId` index with real Suwayomi chapters — progress could be written to the wrong server chapter. All synthetic chapter ids are now **negative** and disjoint from every server id, and every chapter-target collapse is `serverId != 0`-guarded with an identity-checked local-id fallback.
- Offline-created **categories** now use the same reserved negative synthetic range (`IsarService.generateSyntheticServerId()`), matching the manga/chapter convention.

### Offline-category pull safety
A server pull (`saveCategories(replaceAll: true)`) no longer wipes local-only categories:
- Categories with a queued create (pending `SyncAction.create`) are excluded from the deletion set.
- Synthetic (negative) temp ids are always protected.
- `syncCategoryDelete` treats synthetic/pending categories as local-only: it cancels their queued **create AND assign** records instead of leaking them or issuing a bogus server delete.
- The dispatcher's create-remap no longer requires `localServerId > 0`, so negative temp ids remap to the real server id on replay.

### `setMangaCategories` replace-all fix
The batch mutation has no `categories` field on modern Suwayomi (schema-verified) — replace-all now performs `clearCategories` + `addToCategories` instead of a no-op patch.

### Paginated chapter fetching
`fetchMangaDetails` assembles chapters via the paginated root `chapters(condition:{mangaId}, first, offset)` query instead of the arg-less nested `manga.chapters` connection, which silently truncates very long series on stricter servers. Response shape is unchanged (`manga.chapters.nodes`), with a legacy single-query fallback for servers without root pagination.

### Observable QuickJS status
`QuickJsService` now exposes `isInitialized`, `initializationError`, and `installedSourceCount`, so a degraded-but-swallowed init failure is observable instead of invisible.

### Detail dual-resolve + history/migration hygiene
- Manga detail dual-resolves by server id, then by local id when `serverId < 0` — a local standalone can never trigger a server fetch keyed by its local id.
- History surfaces only chapters of manga still in the library.
- Migration treats only server-origin results as server-backed; download state is no longer copied onto target chapters whose files belong to the old source URLs.

## Known limitations (continuing)
- **iOS/macOS**: background transfers still suspend on background — resume-on-foreground with a "Downloads resumed" notification (native `URLSession`/`BGTaskScheduler` remains a future spike).
- **Android 15**: unchanged 6-hour `dataSync` budget (clean pause → resume on foreground).
- Extensions run untrusted JavaScript by design; use the third-party warning (D1) and optional `sha256` verification (D2) to reduce trust.
