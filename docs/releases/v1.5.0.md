# Sunfire v1.5.0 Release Notes

## Overview
**Sunfire v1.5.0** (`1.5.0+1`) is the first feature release on top of the stable `v1.0.0` line. It fixes the three download complaints (backgrounding kills downloads, no notifications, wrong batch order), adds a Mihon/Mangayomi-style end-of-chapter popup, and fixes the release-lineage versioning so upgrading from beta `v11.0.0-beta` to stable `v1.x` is never treated as a downgrade.

> **Versioning note**: betas were tagged up to `v11.0.0-beta`; the stable line restarted at `1.0.0`. Any self-version comparison now uses `RepoManager.compareAppVersions` (stable always beats prerelease), leaving extension semver untouched.

## Changelog since v1.0.0

### Downloads survive backgrounding (Android foreground service)
- `flutter_foreground_task` (v11.0.3) runs a `dataSync` foreground service while the download queue is active — the OS can no longer kill downloads when the app is backgrounded.
- Manifest declares `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_DATA_SYNC` + the `com.pravera...ForegroundService` declaration; `minSdk 24` is pinned (flutter_local_notifications 22.x hard requirement).
- The background isolate re-renders the service notification from a shared JSON snapshot. **Zombie guard**: a snapshot older than 90s (or unparseable) means the UI isolate is dead, so the handler stops the service instead of leaving a permanent "Downloading…" notification. A 30s heartbeat keeps the snapshot fresh during long single-chapter downloads.
- The notification's **Stop** button sends `{'action': 'pause'}` to the main isolate → `pauseLocalQueue()`, so stopping never strands queued work.

### Download notifications
- Ongoing progress (id 4001) via the FGS on Android, falling back to `flutter_local_notifications` **on every platform — including Android when background downloads are toggled off** — so progress feedback never disappears.
- Batch completion summary (id 4002): "Downloads Completed" / "N chapters downloaded" / "X succeeded, Y failed" / "N Downloads Failed". Copy built by the pure, tested `downloadsCompletionSummary()`.
- New settings: `downloadNotificationsEnabled` (default on) and `backgroundDownloadsEnabled` (default on, Android-only), exposed under **Settings → Downloads → Notifications & Background**.

### Correct batch order (chapter 1 first)
- Manga-detail batch selection sorts targets ascending by `chapterNumber`; `sortQueuedTasks` orders the queue by `(mangaId, chapterNumber)` so a 100-chapter batch downloads 1, 2, 3… instead of 100, 99…
- Deterministic `chapterId` tie-break for duplicated chapter numbers (Dart's sort is unstable).
- Queue ordering, batch accounting (`countRetryableTasks`), JSON round-trips (including the new `chapterNumber`), and notification copy all have dedicated practical tests.

### End-of-Chapter popup (Mihon / Mangayomi style)
- Reaching the last page pops a dialog with **Previous Chapter / Next Chapter / Close** — paged mode, webtoon mode, and auto-scroll end (when auto-next is off).
- Shows once per chapter; gated by the new `End-of-Chapter Popup` reader setting (default on).
- The transition-card gradient scrim no longer intercepts taps on the page behind it.
- Chapter next/previous resolution moved to pure, tested helpers (`reader_chapter_navigation.dart`) — identical semantics to the previous inline logic.

### Versioning fix
- `RepoManager.compareAppVersions()`: a stable build always beats any prerelease, so "beta v11 → stable v1" is an upgrade, and 1.5.0 > 1.0.0 numerically. `compareVersions()` (extensions) is unchanged.
- Bumped to `1.5.0+1`.

### Tests added (all passing — 357 total)
- `test/download_features_practical_test.dart` — queue order, batch totals, notification copy, settings defaults/toggles + Wi-Fi gate, FGS snapshot lifecycle, app-version semantics.
- `test/platform_download_wiring_test.dart` — manifest permissions + service declaration, SDK/desugaring/minSdk, iOS plist usage description (+ documents the Android-only background design), plugin registrant checks, `main.dart` init order + pause signal.
- `test/reader_chapter_navigation_test.dart` — chapter-number parsing, sibling sort, next/prev resolution, dialog gating, scroll-progress semantics.
- `test/v1_5_audit_hardening_test.dart` — relative-URL resolution, offline category→assign remap, Date Format wiring, pause persistence (see below).
- `test/beta_v11_features_test.dart` version assertion updated to 1.5.0.

## Full-feature audit pass (same release)

A deep audit of the reader, settings, sync engine, downloads, and platform wiring produced the following hardening fixes (all covered by the passing suite):

### Downloads
- **Pause now truly pauses.** An explicit "Pause" is persisted, so the automatic resume on app start *and* on every foreground no longer silently restarts a queue the user stopped (e.g. to save mobile data). New `resumeLocalQueueAfterForeground()` respects the pause; the UI resume button still overrides it. `main_shell`'s lifecycle handler now calls the guarded variant.
- **Dismiss of an in-flight chapter no longer double-counts.** `dismissLocalTask` marks the task cancelled *before* cancelling the token, so the queue loop recognises the deliberate dismiss instead of also logging a failure.
- **Retry vs new-enqueue accounting.** Retrying a failed chapter replaces its slot (and undoes its logged failure) instead of inflating the batch total; brand-new enqueues mid-batch still grow the total correctly.
- **Stale progress notification on Android-bg-off.** `_stopActiveNotifier` now cancels the `flutter_local_notifications` progress card on every non-FGS path (iOS/desktop **and** Android when background downloads are disabled) instead of only on non-Android.
- **FGS start is foreground-gated.** `startService` is only called while the app is on screen (Android 12+ blocks background starts); if a start is skipped, the resume handler restarts the queue rather than stranding it.
- **Android 15 dataSync timeout → clean pause.** The FGS `onDestroy(isTimeout)` now sends `{'action': 'pause'}` so in-flight chapters stop cleanly at the end of the 6h budget and resume on next foreground.
- **Pause-callback ordering.** `DownloadForegroundTask.initialize()` + `addTaskDataCallback` now run *before* `DownloadManagerService.initialize()`, so a "Stop" tap in the first seconds after launch is never lost.

### Reader
- **Progress flush on chapter switch.** Any pending debounced progress write is flushed when leaving a chapter, so reading the last page and immediately advancing no longer loses the read (mark-read, tracker push, and "delete finished chapter" rules all run).
- **Stale-resolution race guard.** The generation check now runs *before* any state write (source/page list), so a timed-out resolution from a previous chapter can't clobber the current one.
- **No dialog over live auto-scroll.** The end-of-chapter dialog is suppressed while auto-scroll is driving the sheet (its own end-of-chapter path shows it when auto-next is off).
- **Single tracker/scrobble push.** Progress is only pushed to the tracker/Metron when a chapter *transitions* to fully read — previously a re-read of the last page re-scrobbled.
- **Volume-key debounce.** The keyboard volume-key handler shares the same 280ms window as the platform volume listener, preventing double page-turns from a single physical press.
- **Chapter selector highlight fixed** for locally-created chapters (`serverId == 0`) via `findSiblingChapterIndex`.

### Sync engine
- **Deterministic replay ordering.** Same-second offline mutations now replay in insertion order (auto-increment id tie-break) instead of an unstable timestamp-only sort.
- **Offline category → assign remap.** When a category created offline is flushed and receives its real server id, pending `assign` records that referenced the temporary id are rewritten — the server no longer silently drops those assignments. Pure, tested `remapOfflineAssignRecords()`.

### Content resolution & repos
- **Proper relative-URL resolution.** Server page/thumbnail URLs and extension chapter URLs now join via `Uri.resolve` (pure `resolveRelativeUrl()`), fixing broken `//` URLs and base-path collapses.
- **Repo cache write is fail-safe.** A failed repo-index cache write logs + falls through instead of discarding the freshly fetched index.

### Settings & UI
- **Date Format setting is wired.** The General/Appearance → Date Format selection now formats absolute chapter dates in the manga-detail chapter list (relative "Today"/"Yesterday" preserved). `formatDate()` is covered by tests.
- **Library Display Mode dialogs match.** "Cover Only" was missing from the Settings radio (the library toolbar already supported it); now both offer all four modes.

## Known limitations (documented, accepted)
- **iOS/macOS**: background downloads are intentionally not granted (`UIBackgroundModes` absent) — downloads pause when suspended and resume on next foreground (`resumeLocalQueueAfterForeground`).
- **Android 15**: a `dataSync` FGS has a 6-hour budget when fully backgrounded; when it expires the FGS sends a pause to the main isolate so chapters stop cleanly, and the queue resumes on next app foreground. Pinned `minSdk 24`.
- The 90s zombie guard requires the heartbeat; it is cancelled/paused correctly on pause, cancel, delete, and dispose.
- **Server auth errors (401/403)** surface as a `null` GraphQL response and are logged — they don't crash, but a stale/invalid token isn't automatically auto-reconnected. Restart or re-onboard the server connection to refresh the token.
- **Extensions run untrusted JavaScript** (QuickJS) by design (Mangayomi-style trust model); only install extensions from repos you trust. Covered by `extension_security_test.dart`.
- **Unused `downloadWhileCharging` setting**: no battery plugin is bundled, so the toggle is inert (always allowed). Wired when a battery hook is added.
- **`showLanguageBadges` / `selectedLanguages` settings** are stored for Mihon parity but not yet rendered as library badges.
- **Navigation** mixes `MaterialPageRoute` pushes (mostly settings screens) and go_router paths — functionally correct, kept as-is for momentum.
- **Backup "Restore"** is server-driven: the tile explains to upload the `.tachibk` to the Suwayomi server (client-side restore is not implemented).
